# 个人主页进化：设计研究与取舍

研究日期：2026-11-14。研究对象为当前仓库 v42 页面、下列作者的官方网站及两个官方开源仓库。本文记录设计依据和建议，不把参考站的实现、获奖记录或流量归到本项目。外站本轮主要以网页正文、可访问内容及公开源码说明阅读；未对每个外站做完整真机体验或性能测量。

## 先判断这个主页真正独有的东西

现有素材已经能支撑一个鲜明的主张：**把嘈杂的信息，变成可以采取行动的东西。**

- 去雾：让画面变清晰。
- Data Helper：让原始表格变得可用。
- Weather Helper：让天气信息变成出发建议。
- MailHelper：让校园邮件分清轻重。
- NoticeMe：让重要的小事按时到达。

这是对既有项目的编辑性归纳，不是新增的项目成效。相较于泛化的“数据 × AI × 产品”标签，这条线索可以串起计算机背景、业务分析、摄影与网球，也能指导视觉和交互。

建议设计命题：**个人信号观察站 / SIGNAL → SYSTEM**。画面允许大胆、交互允许有玩心，但访问者应当始终能在一个操作内找到作品、履历和联系。

## 改版前 v42 基线的判断

### 已有的好基础

- 真实去雾前后图、原生 range 和图内拖动：已有能承载品牌记忆的动作。
- 四个独立产品和单列的毕业设计：内容有足够厚度；基线中 NoticeMe、Data Helper 两个项目已有真实截图，本轮新增 Weather 首页见文末落实记录。
- 作品、实习、履历、生活、联系入口齐全，五段实习包含在岗经历。
- 保留无 JS 阅读、减少动态效果、手机导航与键盘交互的基础。
- 在岗职责、离线评测、在线规格、固定天气样例等口径区分清楚。

### 进化空间

1. **首页像按顺序排好的模块，缺少一个支配全站的视觉主张。**把“清晰”从一句文案扩展成排版、色彩与交互母题。
2. **四项作品等重，阅读节奏接近。**应有一个重点舞台，再用简洁的次级信息让其余项目顺畅接棒。
3. **事实多，过程证据少。**职责和技术名词已经完整，最有价值的下一步是“发生了什么问题—我怎样判断—做了什么—能看到什么变化”。
4. **生活图像像作品索引，还缺本人声音。**现有通用题材标签可以保留；真实的地点、日期、当时为什么按快门会明显增加记忆。
5. **在线 CV 和下载 PDF 的新鲜度需要说明。**在线已含 NoticeMe；不把未经重新导出核对的 PDF 默认为完全同步。
6. **联系资料完整，但缺少具体合作偏好。**由用户后续确认求职方向、到岗时间等，不能自行写“可立即到岗”或“开放全职”。

## 建议的空间与视觉系统

### 页面节奏

首页推荐路径：**一句主张 → 一个可玩的签名 → 四个真实产品 → 一段判断方法 → 经历摘录 → 生活侧写 → 联系。**

- 首屏：有力度的大字与紧凑的身份资料形成大小对比。中文负责准确表达，英文作为主视觉的一部分；不让无意义英文挤走姓名与方向。
- 作品：整体可筛选/切换，但默认能看到全部。移动端不能依赖 hover，也不能要求先学会拖拽才看到作品。
- 子页：延续同一套色彩、细线、编号与字级；经历页仍适合时间线，CV 仍适合纸面阅读，Life 应让照片占主导，不强行把所有页面做成同一个网格。
- 收尾：大字号联系句＋真实邮箱，给清楚的下一步。

### 颜色与字体建议

- 主体使用近黑墨色、偏白纸色，配一个有辨识度的亮色。亮色用于索引、状态、动作与关键字，避免成为整段正文的底色。
- 深浅对比来自真实内容区块，不用满屏渐变球与重复玻璃卡。
- 中文正文需要足够字号与行距；小号英文索引不得承载唯一的重要说明。
- 英文大字、等宽数字、中文正文形成层级；不为换字体新增不可控外部 CDN 依赖。

### 动效建议

- 签名动作：图像去雾对比，直接、立即、可键盘操作；解释清楚是预生成结果。
- 微反馈：按压、焦点、筛选状态、复制成功，反馈要可见且真实。
- 滚动：只做少量进入与阅读进度，不劫持滚轮，不锁住正文，不给每一行添加弹跳。
- 减少动态效果：关闭装饰循环和位移，保留状态变化与操作能力。
- 未加载脚本时：作品、联系、简历仍然可访问；不让内容默认透明等待动画。

## 内容推进建议

优先补“一个完整可公开的案例”，它的价值高于再增加十个技能标签。

1. **Data Helper：**一份匿名原始数据、问题列表、修复前后、最终导出或看板。说明哪些步骤自动完成、哪些必须由人判断。
2. **Weather Helper：**一次实际出发决策的过程，预报时点、观察时点、球场与结果各自记录；单次故事不冒充总体准确率。
3. **MailHelper / NoticeMe：**短录屏展示一个任务闭环，以及用户为何需要这个功能。先用虚构样例，不要求公开个人信箱和日记。
4. **和宏 / 量化：**有明确公开边界的图表和口径；在岗工作不能因页面需要而写成已交付成果。
5. **摄影 / 网球 / 剪辑：**少量精选、每件一句本人观察，让生活页成为这个人的另一面。

完整待补材料、最小提交格式和接入位置见同目录 [素材补充清单.md](素材补充清单.md)。

## 工程验证建议

- 320 / 390 / 768 / 1280 / 1536 px 检查横向溢出、导航、中文孤字和按钮裁切。
- 键盘操作：主要入口、筛选、模态框、去雾滑杆、复制、关闭与焦点返回。
- 内容口径：四个独立产品、毕业设计单列、五段实习含在岗、Windows 发布范围、固定样例与真实截图的标签。
- 本地测试不等于 CloudBase 线上测速或真机测试；记录实际做过的项目和限制。
- 资源版本号统一；压缩图不伪称原始分辨率；不能通过删掉信息制造性能成绩。
- 不引入后端、不改变 API 契约，不让视觉改造影响独立项目的服务。

本研究不声称本站达到某个奖项、转化提升或性能分数；这些需要真实测量或外部评审。

## 本轮已落实的转译

以下由当前源文件核查确认，与上面的设计建议区分：

- 首页采用暗墨、lime 与纸白的强对比，保留真实去雾比较作为签名动作；作品从等大卡片改为逐项展示，并提供在线应用 / 桌面工具筛选。
- 每项产品新增“一个设计取舍”，从功能清单延伸到为什么这样设计。NoticeMe 的 AI 与提醒调度隔离、Weather 的事前预报冻结均以源代码为依据。
- 新增首页 Field Note 与独立 `data-case.html`，围绕“评分下降”展示留存记录、同尺度比例图、实际 SQL、字段投影和可追溯来源。数字来自真实公开示例，解释保留样本与字段变化的边界。另用明确标注的两行虚构商品示意，让访问者切换字段、理解投影；示意不计入真实结果，始终保留两行。
- 全站新增可点击打开的快速查找，并支持 Ctrl / Command + K；普通页面导航保留，可直接访问作品、履历和联系。
- About、Cases、Works、CV、Life、Contact、去雾页的页头各有自己的视觉重点，同时沿用同一色彩、索引与细线语言；Life 使用已有照片作为主视觉，不补写拍摄地点或日期。
- CV 下载区说明文件版与在线后续更新的关系；已有正文、下载与联系入口保留，去雾和大数据性能措辞收窄到有依据的实现范围。
- Works 的 Weather 预览已接入真实首页截图节选（2026-11-14 13:09 HKT，静态快照非实时）；首页可玩天气仍是固定样例，MailHelper 仍是匿名示意。Weather 后续只需补核心详情、洞察或录屏，MailHelper 完整真实画面与新版双语 PDF 仍优先。

独立事实与招聘路径检查见 [招聘路径审查.md](招聘路径审查.md)；该文档区分了静态核查与主会话负责的运行态/视觉验收。
