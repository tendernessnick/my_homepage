# 后续内容路线：让这次改版继续长出内容

这份路线讲**接下来三次内容迭代分别解决什么问题**，不重复素材采购单。具体文件规格和文字模板请看同目录 [素材补充清单.md](素材补充清单.md)。每次只完成一个清晰目标，资料不足就保留当前真实内容。

## 目前的证据，已经能支撑什么

- **身份与方向：**计算机背景、香港城市大学商业人工智能硕士在读，五段实习含一段在岗；教育和经历可以沿现有在线 CV 追溯。
- **产品能力：**四个独立产品以及单列的图像去雾毕业设计。NoticeMe、Data Helper 有真实截图；本轮另取得 Weather Helper 真实首页并接入 Works（2026-11-14 13:09 HKT 静态快照，非实时）。首页天气可玩区仍是固定样例，MailHelper 仍是 CSS 匿名示意。源码、发布页、真实截图和可解释的工程取舍，比技能熟练度百分比更有说服力。
- **分析判断：**本轮已建立 `data-case.html`，解释 Data Helper 留存的电商数据记录里为何评分下降。它使用项目仓库既有的公开数据实验结果，**是这轮新增的解释性案例页面，不是新招募用户的使用实证，也不是新增商业收益、客户采用或用户提效成果。**
- **个人侧写：**已有照片、网球协会与新闻部经历、真实书影音偏好，可以支撑生活内容；目前还不够支撑详细旅行路线或逐张拍摄故事。
- **英文可达性：**本轮制作的 `en.html` 是为英文招聘方翻译、精炼的入口，不代表全站已经逐页英文化，也不代表已重新导出英文简历 PDF。

## 三次具体迭代

### 第一次：让招聘材料成为同一份可信记录

**目标：**招聘方从中文主页、英文入口和下载简历看到一致的身份、项目范围和时间线。

这次只做版本对齐：把已有在线事实整理为新版中英 PDF；统一学校/学位、机构、项目名称；确认文件与在线记录各自的更新时间。把当前实习继续写成在岗记录，只有已确认成果才改成完成语态。页面的“打开应用”描述入口形态，不能代替服务健康检查。

**完成标准：**NoticeMe 是否纳入文件版、中英文项目数、平台发布范围、实习起止、联系方式均一致；PDF 下载实际保存可打开；英文入口说明其余详细材料的语言；正式站点域名确定后，分享地址和简历二维码使用相同主站。

这是当前最值得先做的内容维护，不需要再加新的展示模块。

本轮服务链接已有一次实际维护：Weather Helper 原 Railway 地址返回 404，依据本地迁移文档和主会话 HTTP 200/健康状态确认，已改为 CloudBase；Data Helper 与去雾服务首次 503、复探 200。后续更新只需延续这种“先核对入口，再描述状态”的做法，不能把一次成功访问当长期可用性证明。详细记录见 [招聘路径审查.md](招聘路径审查.md)。

还应把入口响应与应用加载分开看：Weather 的 CloudBase 测试域首次访问有确认提示；本轮独立环境有成功载入并取得首页，也出现主 JavaScript 长等、正文空白。健康 200 不代表主 JavaScript 一定顺畅；这些是本次环境的观察，不能推断所有用户都会遇到。后续以稳定完成一次实际阅读任务来判断体验，不只看探针状态。

### 第二次：补一个有亲历过程和结果的深案例

**目标：**在“我做了这些工具”之后，增加一次真实的“我为什么这样改，它后来发生了什么”。

从一个产品选择一个具体决策，不同时铺开四个。优先二选一：

- **Data Helper：**用户本人完成一次可重现工作任务，记录输入、人工判断、修复/保留的理由和输出。需要评估时间时，用同样任务和明确环境对照；没有测量就只讲过程，不写百分比提效。
- **Weather Helper：**已有真实首页，不必重复制作；下一步可先补具体球场详情、洞察或短录屏，再记录一次真的约球决策，保存出发前版本、球场/时段、当时建议和到场实况。它可以成为一次体验故事；一次成功或失败都不推成总体准确率。

现有 `data-case.html` 可以作为解释风格的起点，下一篇必须增加新的亲历证据，而不是把同一组 UCI 数字换一套版式重复发布。

**完成标准：**读者能区分输入事实、作者判断和观察结果；至少能看到一个关键取舍；来源、记录时间与限制清楚；涉及真实用户或公司时，有公开范围；没有用测试数量、代码行数替代使用效果。

### 第三次：让人记住产品背后的这个人

**目标：**让 Life 与 About 拥有本人声音，形成与技术案例不同的阅读节奏。

从现有照片里精选一组，配你自己的短手记，或者完成一个“从球场长出来的产品想法”故事。内容可以很短：为什么停下来拍、一次组织训练遇到的问题、剪辑时删掉了哪一段。选一件讲完整，比增加更多兴趣标签更有辨识度。

**完成标准：**有本人叙述而非通用文案；地点和时间按真实记忆填写；涉及组织/团队工作时注明自己的角色；形成一个 3—6 图的主题或一段有说明的视频，不把图库无限加长。

达到这一标准后，再判断是否需要独立 Notes 栏目。先有可读的作品，再增加目录。

## 现在不建议空建的内容

- **空博客、空 newsletter、空作品分类：**没有正文先不做订阅和目录，让首页入口始终有东西可看。
- **数字看板式“个人成绩”：**没有真实数据来源，就不加访客数、用户数、效率提升、收入或 GitHub 假动态。
- **完整虚拟操作系统或大型 3D 世界：**当前最有辨识度的是亲手做过的真实工具与判断过程。新增体验应解释这些内容，而非使履历与联系变难找。
- **自动抓取公司的内部材料：**先明确公开范围，再决定呈现方式；公开数据重制样例应直接标注。
- **一次性全站双语：**当前英文入口已能服务初步阅读。先验证这条路径，再根据实际英文材料补深度页面，避免长期两套内容失配。
